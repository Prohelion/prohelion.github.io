# Profinity 2.3.10

Profinity 2.3 is a major release that modernises security and identity, introduces the tag layer (Tag Explorer, collections, rules, and alerts), adds dynamic plugins and advanced component authoring, improves Linux deployment paths, and ships the Profinity Mobile app with UDP server discovery.

This release targets operators, administrators, and OEM integrators deploying Profinity on desktop, Linux services, and Docker.

## Summary

- Granular **RBAC** with 24 permissions and Security.yaml **`Version: "2.3"`** (roles-only model; legacy groups removed).
- **Site-wide sign-in method** (Local or SSO), optional **global MFA** for local users, recovery codes, and remember-device policy.
- **Tag layer**: Tag Explorer, collections, rules visual editors, and **ALL ALERTS** with live indicators and ack/unack/silence.
- **Dynamic DLL plugins** via Plugin Manager; **Custom Component** advanced authoring and optional **Component Pack** CLI.
- **Session firmware credentials** — Gen2 admin key and Rinstrum passcodes unlock in the UI per login; not stored on disk.
- **Linux default artifacts path** `/var/lib/Prohelion/Profinity` with automatic migration from legacy locations.
- **Profinity Mobile** with **ProfinityHeartbeat** UDP discovery on the local network.
- **Editable dashboards** and an improved visual editor (chart multi-source, `HtmlContent` map bindings).

## Highlights

### Security and identity

- Security.yaml migrates automatically on load to **`Version: "2.3"`**; users are assigned **roles** that bundle permissions (no per-user permission lists).
- OIDC SSO, SCIM provisioning, and SIEM export settings moved to **Config.yaml** (Security Config tab); Security.yaml holds users, roles, and 2FA secrets.
- Password policy (complexity, expiry, forced change) configured under Security Policy.
- Administrators can **Reset MFA** and **Reset password** for other users; operators manage their own MFA from the pill menu when policy requires it.
- **Service accounts** with long-lived tokens for automation and MCP.

### Tag layer, rules, and alerts

- **Tag Explorer** at `/tags` for browsing the tag catalog with quality indicators.
- **Collections** and **rules** visual editors with stable YAML (`version: "2.3"`).
- **ALL ALERTS** at `/tags?view=alerts` — Active and History tabs, live indicators on dashboards and Tag Explorer, dwell/deadband evaluation.
- Rule **action context** (`TriggeredTags`) and **Rule Script** components (C#/Python).

### Components, plugins, and dashboards

- **Plugin Manager** — upload, enable/disable, and hot-reload external DLL plugins (`.nupkg` or zip).
- **Custom Component** supports `actions.yaml`, firmware scripts, `settings_map` / `firmware_map`, and optional pack/install via `profinity-component-pack`.
- **Dashboard Component** — YAML-only profile component (no DBC), distinct from profile home dashboard.
- **Menu layout editor** for profile and component placement in the side menu.
- **Tag linking** from Tag Explorer context menu (add to dashboard, create collection, create rule).

### Platform and mobile

- Linux artifacts default to `/var/lib/Prohelion/Profinity`; `PROFINITY_HOME` override for multi-instance layouts.
- `profinity.sh` launcher preflight checks on Linux publish builds.
- **Profinity Mobile** — install on iOS/Android, discover servers via UDP heartbeat (port 49025), connect with password or kiosk login.

## Breaking changes and upgrades

Review each item before upgrading production systems. OS-specific paths are included where defaults changed.

### Security.yaml 2.2 → 2.3 (roles-only RBAC)

**Who is affected:** All installations upgrading from Profinity 2.2.x.

- Legacy **security groups** are removed. Users receive **assigned roles**; each role holds a list of **permissions**.
- Migration runs automatically when Security.yaml is loaded; the next save writes **`Version: "2.3"`**.
- Changing a user's roles or a role's permissions **revokes active sessions** for affected users.
- Default **Administrators** role includes the full permission bundle, including `McpView` — no manual assignment needed for MCP access.

**Action:** Review role assignments after upgrade. Update hand-edited Security.yaml: `SecurityGroups` → `Roles`, user `SecurityGroups` → `AssignedRoles`, group `SecurityRoles` → role `Permissions`. Replace `SchemaVersion` with `Version: "2.3"`.

See [RBAC and permissions](../Administration/Security/RBAC_Permissions.md).

### OIDC, SCIM, and SIEM in Config.yaml

**Who is affected:** Administrators who configured SSO or provisioning in Security.yaml.

- **OIDC SSO**, **SCIM provisioning**, and **SIEM export** are configured in **Config.yaml** (System Configuration → Security Config).
- **Security.yaml** retains users, roles, 2FA secrets, and external identity links.
- Saving Config.yaml triggers an **engine restart**.

### Site sign-in method (Local or SSO)

**Who is affected:** All multi-user deployments.

- Per-user `AuthenticationMode` and role `RequireTwoFactor` are replaced by site policy:
  - **Sign-in method:** `Local` or `Sso` in Config.yaml.
  - **Enforce two-factor for local users** when sign-in method is Local.
- SSO users authenticate via the identity provider; link accounts with **External identity links** in user settings.
- Hybrid local + SSO on the same site is **not** supported.

See [SSO and sign-in method](../Administration/Security/SSO_and_Sign_In.md).

### Linux artifacts path

**Who is affected:** Linux operators and Docker deployments on Linux hosts.

- Default writable data root is **`/var/lib/Prohelion/Profinity`** (not XDG `~/.local/share/Prohelion/Profinity`).
- On first start after upgrade, Profinity migrates from legacy paths (`~/.local/share/Prohelion/Profinity`, `/var/lib/profinity/Prohelion/Profinity`, and home-based `Prohelion/Profinity` trees).
- Override with **`PROFINITY_HOME`** for staging or multi-instance layouts.

See [Artifacts directory](../Installation/Artifacts_Directory.md).

### Windows and macOS artifacts migration

**Who is affected:** Desktop operators with profiles under legacy home paths.

- Default remains the OS application-data location (`%LOCALAPPDATA%\Prohelion\Profinity` on Windows; `~/Library/Application Support/Prohelion/Profinity` on macOS).
- On startup, Profinity migrates from `~/Documents/Prohelion/Profinity` and `~/Prohelion/Profinity` when detected.

### Session firmware credentials

**Who is affected:** Operators who configure Gen2 BMS or Rinstrum scale firmware.

- Gen2 **admin configuration key** and Rinstrum **setup passcodes** are **not persisted** in component YAML.
- Unlock credentials in the component **Settings** dialog each session; values clear on logout.
- API: `POST/DELETE .../SessionCredential`.

See [Session firmware credentials](../Administration/Session_Firmware_Credentials.md).

### Settings registry and Config.yaml

**Who is affected:** Administrators and OEMs with hand-edited configuration.

- Many system settings now live in structured **Config.yaml** sections with realtime reload where supported.
- Profile-only fields remain in **Profile.yaml** on the legacy path for profile-scoped settings.

See [Settings registry](../Extending_Profinity/Configuration/Settings_Registry.md).

### Collections and rules YAML (`version: "2.3"`)

**Who is affected:** Profile authors using collections and rules visual editors.

- Product YAML documents use **`version: "2.3"`** (aligned with the software release). Re-save collections and rules via the editor after upgrade if you hand-edit YAML.

### Dashboard YAML schema

**Who is affected:** Dashboard authors.

- Editable dashboards, chart multi-source bindings, and `HtmlContent` **map** bindings (latitude/longitude → map iframe).
- Validate custom dashboards against the current schema before deploy.

See [Dashboard visual editor](../Extending_Profinity/Dashboards/Visual_Editor.md).

### Plugin components on disk

**Who is affected:** Admins and OEM integrators.

- User DLL plugins install under `{Artifacts}/Plugins/{pluginId}/` and are managed in **Components & Plugins**.
- Distinct from **Custom Component packs** (zip/nupkg of YAML and scripts via `profinity-component-pack`).

See [DLL plugins](../Extending_Profinity/Plugins/index.md) and [Component Pack CLI](../Extending_Profinity/Components/Component_Pack_CLI.md).

### Tag layer APIs

**Who is affected:** API integrators.

- New `/api/v2` tag, collections, rules, and alerts endpoints supersede legacy patterns.
- `DataController` is removed from the v2 API surface — use tag-layer controllers for new integrations.

See [Tag layer](../Extending_Profinity/Tag_Layer/index.md) and [REST APIs](../Extending_Profinity/APIs/index.md).

### Installer version text

**Who is affected:** Release and support teams.

- Engine version is **2.3.10**. Installer metadata now correctly displays 2.3.10.

## Upgrade checklist

1. **Back up** `{Artifacts}/Config/` and `{Artifacts}/Profiles/` before upgrading.
2. Upgrade Profinity to 2.3.10 and start the engine once to allow path and Security.yaml migration.
3. Review **logs** for artifacts migration messages (especially on Linux).
4. Sign in as an administrator and verify **Users & Groups** → **Roles** and user **Assigned roles**.
5. Open **System Configuration** and confirm **Sign-in method**, password policy, and SSO/SCIM/SIEM settings.
6. Run `npm run validate-dashboards` on any custom dashboard YAML in documentation or profiles (see extending dashboards guide).
7. Update automation, backups, and Docker volume mounts to the new Linux path if applicable.
8. Re-test firmware unlock flows for Gen2 and Rinstrum components.
9. Change default `admin` password if not already done.

## Known issues

- **Tag relay / federation** is partial and not documented for GA — do not enable in production without engineering guidance.
- **Reciprocal tag linking** (e.g. add rule from collections editor context menu) is not shipped in 2.3 GA — Tag Explorer context menu flows are supported.
- **NuGet feed publish** for plugins is not GA — install local `.nupkg` or zip via Plugin Manager only.
- Android emulators cannot receive LAN UDP heartbeat broadcasts — use a physical device for mobile discovery testing.
