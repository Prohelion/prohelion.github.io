# Profinity 2.3.6 release notes

Profinity 2.3.6 makes every logger, historian, and publisher handle every kind of tag value in the same way.
A tag that holds text, a date, an identifier, or a list is now logged and published as what it is, and a tag that a destination cannot hold is reported once in the log.
These notes cover the logging, history, and publisher changes.
For the upgrade from Profinity 2.2, refer to the [Profinity 2.3.3 release notes](2.3.3.md).

## Logging and history

An InfluxDB historian or logger no longer stops logging when a tag holds a list of values, such as a firmware setting that is a table.
Before this release, an InfluxDB v2 historian in **Snapshot** mode logged `writing failed` and wrote nothing while any tag held a list.
A list is now stored as JSON text, such as `[0,500,1000]`.

The InfluxDB historians and the InfluxDB v1 Logger write a tag that does not hold a number to a `text` field, and record the kind of value in a `valueType` field.
The historians read history back as the kind of value that was written.
[InfluxDB historians](../Components/Historians/InfluxDB_Historians.md) describes the fields, and [What each destination holds for a tag](../Components/Logging_Modes.md#what-each-destination-holds-for-a-tag) covers every destination.

Viewing a dashboard at a past time, and reading stepped history, now return values from the InfluxDB v2 and v3 historians.
The InfluxDB v2 historian returned no value for a past time, and the InfluxDB v3 historian missed readings with some server versions.
[How to view a dashboard at a past time](../How_To_Guides/View_Dashboard_at_a_Past_Time.md) explains the control.

The TAG Local Historian, the TAG SQL Historian and the InfluxDB historians now read history back in the same way for every kind of value.
A SQL historian that was added and then removed before a connection string was set no longer raises an error.

## Publishers

The MQTT Publisher with **JSON**, and the Webhook Publisher, send text, true or false, dates, identifiers, and lists as well as numbers.
A list is sent as a JSON list.
Before this release, these publishers left out every tag that did not hold a number, without a message.
The [MQTT Publisher](../Components/Publishers_and_Subscribers/MQTT_Publisher.md#payload-formats) and the [Webhook Publisher](../Components/Publishers_and_Subscribers/Webhook_Publisher.md#payload-format) pages show the payloads.

The MQTT Publisher with **Sparkplug B** publishes the datatype that matches each tag, in place of a double for every tag.
A tag that is new, or whose kind of value changes, is announced again before its data.

## Behaviour that changes

Check these when you upgrade, because they can change what a query or a subscriber receives.

- Text that looks like a number, such as `12.5`, stays text. Before this release, InfluxDB could store it as a number, and the publishers could send it as a number.
- A Good tag with no value is no longer written to InfluxDB, or sent by a publisher, as `0`.
- A number that InfluxDB cannot hold exactly, such as a whole number above 9,007,199,254,740,992, is stored in the `text` field so that it is never rounded.
- A derived tag whose expression returns a list reports Good quality and holds the list as JSON text. Before this release, it reported Bad quality.

## Skipped tags in the log

A destination that leaves out a tag now writes one warning that names the tag, the destination and the reason, and does not repeat it on every interval.
The reasons are a number that is not finite, text over the 64 KB limit of an InfluxDB text field, a tag that is not a number on the [Prometheus Logger](../Components/Loggers/Prometheus_Logger.md), and a tag whose value Profinity cannot read.
A tag whose value cannot be read no longer stops the tags after it from being written or sent.
Read the warnings on the [Logs](../Administration/Logs_Config.md) page under **ADMIN**.
