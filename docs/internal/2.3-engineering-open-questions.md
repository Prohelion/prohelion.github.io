# Profinity 2.3 engineering open questions

**Raised by:** the 2.3 documentation quality pass (October 2026). **Not published:** this page is under `docs/internal/` and is excluded from the built site.

Each item is something the docs now state, or avoid stating, because the code did not settle it. Tick an item when engineering has confirmed it, and tell the documentation owner so the page can be changed. File references are in the Profinity repository.

Settled during the pass and no longer open: the time-window default (`-10m` everywhere), the BACnet device instance check, the Windows Desktop login and loopback behaviour, Industrial Protocols as an add-on on stock licences, the Rinstrum chart window, and the release notes page name.

## Defects to check first

- [x] **CAN replay may not transmit on the bus.** Settled: replay never transmits. `TransmitOverNetwork` and its `SendMessage` branch were removed from `CanBusReplayService`, with a scenario guarding it (`can-replay-isolation.feature`). Send and Receive page says "never".
- [x] **`publishStateTagPath` is missing from `rules.schema.json`** (settled: added to the schema and the AI Skills copy, with a save-validation scenario), and the rule item rejects unknown properties. `RulesYamlSchemaValidator` runs on save (`ProfileRulesYamlPersistence.cs:54,191`), so saving a rule that sets it may fail. The docs describe the setting only through the **Publish state tag path** editor field.
- [x] **Themes and branding have no licence entitlement** (settled: `ProductFeature.Themes` added to Desktop, Server, Enterprise and Trial; an unlicensed host serves the default theme. Commercial still to sign off the Licensing and Theming wording) in `ProductFeature.cs`. The Licensing page says Desktop and above with white-label rights, and the Theming page says Profinity does not block an unlicensed instance. Add the entitlement, or change the commercial position (Commercial to sign off the wording).
- [x] **MQTT Publisher in JSON mode never reconnects.** (settled: JSON mode now uses the shared `ConnectionMaintainer` with the same 5 second delay as Sparkplug B; the initial connect is still not retried) The connection is made at start and `SendAsync` throws when it is lost (`MqttPushTransport.cs:105-110`, `PushPayloadPublisherBase.cs:166-168`). The 5 second reconnect applies to Sparkplug B only (`MqttPublisher.cs:163`). The page now says a lost connection stays in **Error** until the logger is restarted.
- [ ] **Release notes claims taken from the plans** need confirming before publishing: the REST error shape (A30), the firmware passcode change (A12), documents rewritten on load or save (A24), and `config.yaml` rewritten on save.
- [x] **Windows service:** settled from the code. `ProfinityService.cmd` registers `Profinity.exe` (the Desktop GUI, which starts the engine with `isDesktopHost: true`), so the service is a desktop host: it binds to loopback only and a Server licence does not change that (`LicenseNetworkPolicy`, covered by `EnforceRemoteWebServerPolicy_DesktopHost_ForcesLoopbackEvenWithServerLicense`). The service page now says so. Still open: `Running_As_Service.md` also says Profinity runs in server mode on Windows; the only Windows host in source is the desktop application, so confirm whether a non-desktop Windows server host exists.

## Tags, rules and alerts

- [ ] Component rules with a nested tag tree path: the loader seeds the component name only (`RulesYamlLoader.ResolveComponentBasePrefix`). The Tag Tree Path page does not say how a component's own rules are scoped.
- [ ] `relatedTags` is stored with a rule but the Alerts Log detail dialog (`AlertDetailDialog.tsx`) does not show it.
- [ ] The Alerts Log offers Acknowledge and Silence (fixed 1 hour) but has no Unacknowledge control; the docs say Unacknowledge is API only.
- [ ] `Math.Abs` and `Math.Round` on a nullable double in derived tag formulas are untested.

## Components and protocols

- [ ] **BACnet:** the new device identity check (reads the Device object with the wildcard instance 4194303 and compares `Object_Identifier`) has not been tried on a real device. The reply handling now has unit tests (`ManagedBacnetClient.ParseDeviceInstance`), so only the real-device trial remains. Existing configurations with the default instance 0 stop reading until set.
- [ ] **OPC UA server:** the docs say it listens on localhost only with the default **Bind URL** (`OpcUaPki.cs:136-144`, plugin README). Confirm with `netstat` on a running server. Confirm the certificate folder `opcua_pki` for the Docker and service installs, and which security mode the client's **Use security** option selects (`FoundationOpcUaSession.cs:39-42`).
- [x] **Read failures log at debug level** settled: a shared `OutageLog` now reports a failing read, poll, write or send once per outage (a warning with the reason, repeats at debug, a note when it works again) in the Modbus, BACnet, S7, EtherNet/IP, OPC UA and Rinstrum plugins, the MQTT publisher, Tag Relay sender, SQL and InfluxDB historians and loggers, the Prometheus logger and the TDK and Siglent chargers. Point-level wiring is covered by the helper's unit tests; there is no per-component log-capture test.
- [ ] EtherNet/IP: the CIP path for a remote chassis or bridge, and whether PLC-5 and SLC want it empty.
- [ ] TAG SQL Historian: an example connection string per provider, the privileges required and the SQLite file location (not derivable from source).
- [ ] InfluxDB v2 and v3 historians: token permissions, whether InfluxDB Cloud is supported, and a stale code comment (`InfluxDbHistorianV3Settings.cs:59-61`) saying the v2 Dashboard URL defaults to the server URL when no code does. The stale `DashboardUrl` comment is fixed (no constructor defaults it to the server URL); token permissions and InfluxDB Cloud support remain open.
- [ ] Prometheus logger: **Server Hostname** goes straight to the prometheus-net listener (`PrometheusMetricHost.cs`). Can `localhost` be scraped from another machine, do `+`, `*` and `0.0.0.0` work, and does Windows need a URL reservation?
- [ ] Prohelion Cloud Dashboard: where do the access token and device ID come from, and should the firewall note name the cloud host (hard-coded in `ProhelionCloudDashboardSettings.cs:49`, outbound port 1883)?
- [ ] Tag Relay: how does a user get the JWT for HTTPS relay and how long does it last, is `POST /api/v2/Relay/delta` public API, and what happens with zero HTTPS receiver components?
- [ ] Webhook retry numbers (3 attempts, 1 s, 2 s, 10 s) are recorded in code as not user-confirmed (`WebhookTransportOptions.cs:70-76`). Publisher start gate: the failure reason is discarded (`LoggerDeviceBase.cs:74-79`), so no log message is promised.
- [ ] Chargers: how does a user connect a TDK or Siglent supply manually when **Auto Connect** is off, and does a D1000 Gen2 charge through the Profinity screen (**Control Pack** defaults to false, `BatterySettingsBase.cs:16`)?
- [ ] BMS firmware: which tab of the settings dialog shows the **Firmware Configuration Key** row, is the Admin key documented publicly, and are Peak and CANdapter adapters available outside Windows?
- [ ] WaveSculptor200: there is no component or DBC in source; the docs say a Custom Component with the WS200 DBC can monitor it. Confirm.

- [ ] Charge component: `defaultBatteryId` is optional but the Start action does nothing without a battery id. Intended?

- [ ] Should Icon, HTML and Redirect move out of the Interactive category? Is `/api/v2/ActiveProfile/Component/{name}/settings` the supported settings address for the **modal** menu item? Does the BMU cell voltage dashboard named in the Tables example ship with the product?
- [ ] Security tab layout, the Menu Layout path and the SSO recovery step (`config.yaml` key) are documented from source, not the live GUI. Confirm in the GUI. Can the built-in admin on an unlicensed Desktop host be the Kiosk Mode user? How is the maximum concurrent sessions limit enforced (`UserService.cs:624`)? What does a SIEM event line look like?

## SDK, scripting and plugins

- [ ] Where does `example_scripts` live on an installed system, and does **Log Script Output** control whether Console output reaches the Profinity log?
- [ ] Do `profinity-script` and `profinity-component-pack` need a .NET 10 runtime, or are they self-contained?
- [ ] Plugin authoring (base type, manifest, `dotnet pack`) is not documented anywhere. Engineering input is needed for the Plugins page.
- [x] Defects in engineering files: `Profinity-SDK/README.txt` does not say to run `sim` from the new folder, `PythonRunTemplate.py` uses `CanPacket` (should be `CanBusPacket`), and `LuaScriptMetadata.cs` says Lua 5.1 although the runtime is Lua 5.4. Settled: the README now says to `cd` into the new folder before `sim`, the Python templates use `CanBusPacket`, and the Lua description says 5.4 (checked against the embedded runtime).
- [x] `onTrue` and `onFalse` were removed from the rules schema, but other docs outside the customer pages may still use them. Settled: no YAML, example or doc uses them; the names remain only as internal C# identifiers for the runtime action lists.
- [ ] **Public API:** `DataSource.DefaultLocalSeriesTimeRangeStart` changed from `-5m` to `-10m`, recorded in `PublicAPI.Unshipped.txt`. Constants are inlined at compile time, so plugins built against the old SDK keep `-5m` until rebuilt. Decide whether that needs a release note for plugin authors.

## Connection behaviour (added with the shared connection work)

Settled: everything that connects now retries from the start through `ManagedConnection` (see `Docs/Architecture/System/connection-management.md` in the Profinity repository). Open points for engineering:

- [ ] **Backoff was dropped.** The MQTT and Tag Relay subscribers backed off from 1 s to 60 s; they now retry at a steady 5 s. Confirm that is acceptable for a broker that stays down for hours, or add an optional backoff to `ManagedConnection`.
- [x] **Rinstrum firmware settings reload** now runs on every established session (the controller raises `SessionEstablished`), so a scale that connects late or reconnects reloads them. Settled.
- [ ] **BACnet identity check** still runs at poll level, so a device with the wrong instance stays connected but unread. Decide whether the check belongs in the open step so it shows as an Error.
- [ ] **Poll-loop base (G5)** is not done: the six plugin controllers still share about 200 lines each of poll loop and write-error mapping.
- [ ] **Customer docs** now describe the new behaviour (a Connections and Reconnecting page, the component pages and the release notes), but the Rinstrum component has no customer page to update.
