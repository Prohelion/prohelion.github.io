## Section-level observations

- **No clean first-success path.** Quick_Start is the tutorial, but it has branches and reference detail; Write_Your_First_Script is a tutorial with a how-to title. Split each into one linear tutorial and move the rest out.
- **Missing pages a reader would expect.** Installation has no index.md and Getting_Started has no index.md. There is no "Upgrade from Profinity 2.2" page in Installation, although the procedure is linked from six pages. There is also no "Check your installation" or "choose your install method" landing page with prerequisites.
- **Installation pages have no prerequisites or verify steps.** Windows, Zip, Docker, Migration and Running_As_Service lack a prerequisites section, and the first-run check is in prose on most of them. Add the same "Before you start" and "Check it worked" blocks to each.
- **Licensing content sits in install pages.** The hardware and licensing admonition is in Zip_Installation, the restart note sits after the checks in Applying_a_Licence, and the desktop-licence wording in Windows_Installation needs correcting (Camerons' notes). Licensing and the fingerprint section should be the one home for these.
- **Environment variables are documented three times.** Configure_Environment_Variables, Installation/Environment_Variables and the Docker production section overlap. Camerons asks for this to be consolidated in Environment_Variables, which fits the split above. Note that Applying_a_Licence links to the fingerprint section in Licensing, so keep that anchor when Licensing changes.
- **Factual conflict and a broken reference to fix first.** The macOS data location in the 2.3.1 breaking-change text disagrees with Artifacts_Directory. The Docker page says the published compose file includes Watchtower, which the compose file on that page does not. Its troubleshooting also points to "Directly Accessing Devices", an admonition title rather than a heading.
- **Refactor with link hygiene.** "Upgrading From 2.2" (2.3.1.md) is linked from Windows_Installation, Zip_Installation, Migration, Docker_Installation and 2.2.5, so keep that anchor or add a redirect when it moves (style guide section 1). Title Case headings are widespread (about 212 by heuristic across 37 pages), mostly in the long pages. Convert them when each page is refactored, not in bulk.
