# Customising_Profinity structure audit (Profinity 2.3)

Scope: 39 pages under `Customising_Profinity/`. Read-only audit; no docs edited.
Docs root: `docs/Profinity_Software/Profinity_Version_2.3/` (paths below are relative to it).

Method and caveats:
- Word counts are approximate prose words, code blocks excluded.
- `declared_type` is `none` on every page. No page in the section has a `type:` front matter field.
- Duplicates were confirmed with `grep -F` across the whole 2.3 tree and the wider docs root, not inferred.
- Dashboard pages were read in full. Component reference pages were reviewed through headings, parameter tables and a sample, not every line.
- All relative links and image targets in the section resolve. No broken links were found.
- Reviewer notes (`Camerron's Document Review notes.md`) were checked. None of them concern a page in this section. The "Custom Components" note points at `Components/Custom_Components/`, outside this section.
- `TITLE_CASE_HEADINGS (n)` is a heuristic: headings with at least 60 percent capitalised non-small words after the first word, so it can over-count acronyms and proper nouns. Treat the counts as a guide, and check the headings by eye when rewriting.

## Section-level observations

- No page in the section declares `type`, `owner` or `last_reviewed`. All 39 are missing, so every page needs front matter when it is refactored.
- The section has three pages that mix two or three types (Dashboards/index, Data_Binding, Examples). Those three, plus Troubleshooting and Hosting, should be split or rewritten first.
- Most of the duplication is between this section and How_To_Guides (Create_Custom_Dashboard, Create_Profile_Dashboard, View_Dashboard_Source, Debug_Dashboard_Issues). Keep one how-to home for each procedure and link the concept and reference pages to it.
- Profile_Directories conflicts with Administration/Profiles.md on folder count and on `profile.css` case. Fix this before anything else in the section, because it is a factual error.
- Within the section, Image and Model share the same overlay parameter tables, and Conditional_Styling and Data_Binding share the targets table. Extract one shared overlay page and one shared targets reference.
- Heading case is the most widespread style issue. Data_Binding (22 of 22), FAQ (30 of 30) and Image (31 of 31) are almost entirely Title Case. Convert to sentence case as each page is refactored, as section 1 requires.
- Diagrams are missing where the style guide asks for them. Data_Binding and the six component pages with no figure need a data-flow diagram, and sibling component pages should reuse the same one.
- Caption and Redirect sit in categories that do not match their function. Moving a page changes its URL, so add a redirect for any move.
