## Cross-cutting checks requested in the brief

### (1) Log-level sentence (Warning, Debug, Info) against the code
Verified in /Users/ctuesley/Work/Profinity:
- `Profinity-SDK/Profinity-Component-SDK/Utilities/Threading/OutageLog.cs`: first failure after a success is `Warn`, later failures in the same outage are `Debug`, the first success that ends an outage is `Info` ("working again").
- `Components/PolledDeviceController.cs` owns one `OutageLog` per component instance. `PollOnce` calls `outage.Failed("read of <point>")` per failing point, `outage.Failed("poll")` when the whole poll throws, and `outage.Succeeded()` only when a full pass over the point map had no failed point.
- Derived classes: `BacnetDeviceController`, `ModbusController`, `S7PlcController`, `EtherNetIpPlcController` and `OpcUaClientController` all inherit `PolledDeviceController`. So the sentence is correct for all five polled protocols, including the OPC UA client.
- `OpcUaServerController` is `sealed class ... : IDisposable`. It is a listener, not polled, and has no OutageLog. The pages claim this only for the client ("The Log records the first failed read..." sits under the client/polled-values text; Connections page says "OPC UA client components"). Wording is accurate.

Nuances the sentences slightly overstate (all low):
- "the first success afterwards" is in fact the first poll in which every point read succeeds, not the first single point that reads. The outage state is per component, not per point. A point that keeps failing keeps the outage open. Suggested wording if precision is wanted: "the first poll in which every point reads correctly".
- Failed writes are not logged by this path (only reads and whole-poll failures). The five protocol pages say "failed read", which is right. The Connections sentence "log failed point reads in this way" is also right. The pre-existing general paragraph ("read a value, write a point or send a message") is unchanged original text.
- OPC UA wording sits at the end of the Dashboard section, under no heading about bad quality (see page findings).

### (3) "Changed in Profinity 2.3" label on the OPC UA listening note
- Original sentence: "A Bind URL with a host of 0.0.0.0 or localhost, which older versions of Profinity saved as the default, is treated in the same way." It carries no version label and says "older versions".
- Release_Notes/2.3.1.md, section "OPC UA Server Listens on This Computer Only by Default": the server now listens on 127.0.0.1 only unless given another address; "an earlier build listened on every network interface by default while the documentation said localhost only"; a Bind URL saved as 0.0.0.0 or localhost is treated as 127.0.0.1. So the behaviour is a documented change, and the substance of the note is supported.
- But the label is not cleanly supported. There is no OPC UA content in the Profinity 2.2 docs (grep found none), so the OPC UA plugin is new in 2.3 and the "earlier build" is a pre-release or earlier 2.3 build, not a released earlier version. The change is recorded under 2.3.1, a patch release, and the project rule is that only the release notes page may say 2.3.1 and every other page says 2.3. "Changed in Profinity 2.3" therefore tells a reader of a release that never had the old behaviour that something changed from 2.2.
- Recommendation (medium): either drop the label and state the mapping as a plain fact in the paragraph ("A Bind URL with a host of 0.0.0.0 or localhost is treated in the same way, so a profile saved with either listens on 127.0.0.1 only."), or keep the note but have the owner confirm the label wording. G2 itself flagged it as inference; I agree it is inference. Also the note says "older versions of Profinity", a phrase the release note does not support ("an earlier build"). Wording and placement (self-contained, at the bottom of the section, removable) otherwise follow the style guide.
