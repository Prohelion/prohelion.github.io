## Questions for the product owner

1. The InfluxDB Health Check is described differently: the v1 Logger says "Performs a health check on the connection at regular intervals", while the v2 and v3 Historians say "Checks the health of the InfluxDB server when the component connects". Is this a real difference? Both kept.
2. The v2 and v3 Historians list **Allow Retrieval** (default On), but the TAG SQL Historian has no such setting, and its **Designated tag historian reader** row gives no default. Is the SQL historian always retrievable, and is the default Off as on the InfluxDB pages?
3. TAG SQL Historian "Logger settings" heading sits on a historian page. Kept as written. Should it read "Recording settings"?
4. Log message `Failed to start the InfluxDB logger` appears on both historians (the word "logger"). Kept literal. Confirm the shipped text.
5. File loggers: Update Interval is 10 to 86400 but the InfluxDB Logging Interval minimum is 1, and the Prometheus Update Interval is 10 to 86400. Confirm these are intended.
6. The Loggers index links this page as "Virtual CAN adapter" and calls the CAN page "CAN bus adapters", but the Virtual page title is "Prohelion Virtual CAN Bus Adapter" (a product name, so kept). Align the index link text or the title.
7. Bus number limits: the CAN page says V1 bridges support 0 to 15 but Profinity accepts 0 to 13 for V1, and the default is 13. Kept as written. Confirm the 0 to 15 claim.
8. File_Loggers: "Archive File Limit ... applies to the remote files for the SFTP loggers" while the SFTP loggers do not show **Archive the Logs**. Kept as written.

## Diagrams added (all flowchart LR, no colours, check on the built page)

Supported by "writes the values of the tags in the collections you select to an InfluxDB v2 server, and allows that history to be read back out through the APIs". The arrow shows the write path only. The read-back is in the caption.
- TAG SQL Historian: same shape, ending at a table in the SQL database. Supported by "writes the values of the tags in the collections you select to a table in a SQL database".
- File and tag loggers: CAN bus messages and Tag collections each to a File logger, then to Local log files and an SFTP server. Supported by "write either native CAN bus messages or the values of the tags in selected tag collections to a file, which can then be stored locally or transmitted remotely to an SFTP server".

Supported by the page text that InfluxDB expects data to be pushed whereas "Prometheus treats Profinity as a source of data and calls it". The Prometheus arrow runs in the data direction, and the caption states that Prometheus calls Profinity.
