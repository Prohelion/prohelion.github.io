(that is, two built-ins plus four action types, which may be what "two built-in" and "four" refer to: the two built-ins Profinity Log and None, and the four component actions). The audit read it as a contradiction (two built-in then four listed). Original wording kept. Please confirm the intended count and wording.
2. Actions.md: the diagram alt text still reads "(log, Slack, PagerDuty or a script)". PagerDuty is not a documented action anywhere on the page. Original alt text kept. Please check `2.3-diagram-rule-actions.png` and confirm whether PagerDuty appears in the image or is an error.
3. Collections: the reviewer note asks for a statement that Profinity 2.3 writes collections YAML with `version: "2.3"`. Nothing on the original page or on Rules.md says this. Rules.md shows `version: "2.3"` only in the rules.yaml example. Not added.
4. Collections: the reviewer note asks that the collection id "cannot be changed once created". The original page says only that rules refer to a collection by its identifier, which "stays the same when you rename it", and Rules.md shows `collection: CellVoltages`. The page keeps that wording. The stronger "cannot be changed once created" is not supported by either page, so not added. Please confirm, and say where the id is shown in the editor.
5. Page titles versus H1: Actions has title "Actions" and H1 "Rule actions"; Rules has title "Rules" and H1 "Tag rules"; Collections has title "Collections" and H1 "Tag collections". The style guide wants the H1 to match the title. Left as in the original because renaming a title changes navigation.
6. Alerts.md: the **Silence alert for 1 hour** button implies a fixed one-hour silence. The page does not say what happens at the end of the hour. Not added.
7. Script_Driven_Derived_Tags.md has no explicit licence or prerequisite and no verify step. Actions.md says Scripting is licensed from the Desktop edition up, but only for Run On Alert, so I did not carry it across. Please confirm whether scripts used as derived tags need the Scripting feature, and what a reader should check in Tag Explorer to confirm the tag has a value.
8. Derived tags: the "state restored from the alert log" claim in Rule state publishing and the "Rule expressions are not checked" sentence were kept verbatim; flag if either is out of date.
